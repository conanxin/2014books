# Phase F — 阅读系统设计笔记

## 背景

Phase E 已解决视觉风格问题：页面从简单项目展示升级为杂志风首页，配色、排版、信息架构都达到了"年度阅读特刊"的质感。但 Phase E 的输出仍然是单页全文——所有 45 章内容堆叠在一个 HTML 文件中。

## 为什么单页全文不够好

1. **加载与滚动负担**：45 章内容总量超过 300KB HTML，移动端首次加载后需要极长滚动才能定位到特定章节。
2. **阅读上下文丢失**：读者打开第 23 章时，浏览器地址栏仍然是 `index.html`，无法分享"我正在读这一章"的状态。
3. **导航困难**：虽然有锚点，但长页面中的目录跳转体验粗糙，尤其移动端几乎无法使用。
4. **没有阅读进度感知**：读者不知道自己读到哪里，也无法在重新打开页面时恢复位置。
5. **没有阅读偏好记忆**：字号、配色每次打开都重置。

## Phase F 要解决什么

把项目从"单页杂志展示"升级为"可长期阅读的数字杂志系统"。重点：

- 独立章节页：每章有自己的 URL，可分享、可书签
- 阅读进度条：视觉反馈当前阅读位置
- 阅读模式：字号、纸张/夜间偏好，持久化到 localStorage
- 移动端目录：解决小屏幕导航问题
- 主题路线：帮助读者按兴趣选择阅读路径，而不是按顺序硬读 45 章
- OG 分享信息：让分享链接时有好看的预览卡片

## 为什么不改变 97 本书单事实

Phase D 的书单审计结论是：原始附录只有 97 条可靠书目，"100 本"是原始营销标题。Phase F 继续尊重这一事实：

- 正式 book archive 保持 97 本
- 候选书目继续独立隔离在 `data/candidate_books.json`
- 阅读路线中引用的书名只从可靠来源选取
- 不伪造、不臆测、不填充

## 技术约束

- 不引入外部 CDN
- 不引入复杂前端框架
- 保持 Python 标准库静态生成
- 不破坏 PDF / EPUB / release / Pages workflow
