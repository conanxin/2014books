# Phase E 杂志风改造设计笔记

## 当前页面为什么"太简单"

1. **信息层级扁平**：所有内容挤在一个长页面里，没有封面区、没有导语区、没有分区节奏。用户打开页面看到的是章节目录和搜索框，缺乏"这是一本特刊"的仪式感。
2. **视觉语言偏后台工具风**：圆角卡片、阴影、蓝色按钮——这些元素适合 SaaS 产品，不适合阅读体验。页面看起来像数据管理后台，而不是一本可以读的书。
3. **章节之间无区分度**：45 章全部以相同卡片样式堆叠，没有重点章节引导，也没有快速浏览的摘要。
4. **书单和正文混排**：每章末尾的书单卡片和正文挤在一起，阅读流被打断。
5. **状态信息过于技术化**："当前已结构化整理 97 本"像系统日志，不像编辑导语。

## 当前页面为什么"不适合阅读"

1. **字号偏小**：正文 16px 在桌面端阅读偏累，杂志/长文阅读通常需要 17~19px。
2. **行高保守**：1.8 行高对中文来说刚好，但段落间距不足，模块之间缺乏呼吸感。
3. **无阅读焦点**：没有 hero 区吸引注意力，没有 featured 内容引导深入，用户不知道从哪里开始。
4. **搜索是唯一交互**：除了搜索，用户只能滚动。没有锚点快速跳转、没有返回顶部、没有视图切换。
5. **移动端只是缩小版**：没有针对小屏幕重新编排信息优先级。

## 杂志风改造的设计理由

### 为什么用"杂志风"而不是"博客风"或"文档风"

- 原始内容来自《第一财经周刊》专题，本身就是杂志特刊形式。
- "100本书"是一个年度盘点，天然适合 issue-like 的呈现方式。
- 杂志风强调**阅读节奏**和**信息层级**，不是单纯装饰。

### 核心设计原则

1. **封面感优先**：打开页面第一眼要知道"这是什么"、"有多少内容"、"值不值得读"。
2. **编辑感文案**：把技术状态翻译成编辑导语，让用户感受到内容背后有人整理、有判断。
3. **分层阅读**：
   - 第一层：hero → 知道主题
   - 第二层：editor's note → 了解背景
   - 第三层：featured chapters → 快速进入精彩内容
   - 第四层：full archive → 深度浏览
   - 第五层：book list → 检索具体书目
4. **克制配色**：暖白纸张底色 + 深灰正文 + 单一辅助色（暗红/棕金），避免多色干扰阅读。
5. **字体区分**：标题用衬线体（更有书卷气），UI 用无衬线体（更清晰），正文用衬线体（更适合长读）。
6. **留白即节奏**：模块之间用留白和细线分隔，而不是卡片阴影。

### 为什么保持静态生成

- 不引入外部 CDN：保持离线可用、GitHub Pages 兼容、长期可维护。
- 不引入框架：Python 标准库生成 HTML + CSS + 原生 JS 足够，避免构建复杂度。
- 保留搜索：前端 JS 搜索已验证可用，继续保留。
